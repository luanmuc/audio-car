> 状态：方案已确认，待开发
> 日期：2026-11-10
> 目标：限制 App 使用人数，只有拿到激活码的人才能使用

## 一、整体架构

```
┌─────────────┐     HTTPS      ┌──────────────────┐
│  车机版 App  │ ◄────────────► │ GitHub 公开仓库    │
│  (手机/车机) │                │ activate.json    │
└─────────────┘                └──────────────────┘
       │                                ▲
       │ 本地存储                        │
       ▼                                │
┌─────────────┐                ┌──────────────────┐
│ AsyncStorage │                │  手机端管理网页    │
│ (设备ID+令牌) │                │  (管理员后台)     │
└─────────────┘                └──────────────────┘
```

**三个核心组件**：
1. **App 端**：激活码输入、设备指纹采集、本地验证、联网回呼
2. **GitHub 公开仓库**：存激活码哈希列表、设备绑定信息（加密）、过期时间
3. **手机端管理网页**：管理员生成/禁用/解绑激活码，纯前端调用 GitHub API

## 二、安全设计（七层防护）

### 1. 激活码哈希存储（防泄露）
- json 里**不存明文激活码**，只存 SHA-256 哈希
- 用户输入激活码 → App 本地计算哈希 → 去 json 里匹配
- 就算 json 公开了，别人也看不到原始激活码（反推不出来）

### 2. 设备信息加密存储
- 设备 ID、设备型号、激活时间用 **AES-256** 加密后存 json
- App 端和管理网页端共用同一个解密密钥
- 就算 json 公开了，别人也只能看到一串乱码

### 3. 签名令牌防伪造
- 激活成功后，服务器（json）返回一个**签名令牌**
- 令牌内容：deviceId + expireAt + signature（用密钥签名）
- App 启动时验证令牌签名对不对
- 对 → 真的激活了；不对 → 伪造的，弹激活框

### 4. 网络时间防改时间
- 不用手机本地时间判断过期，用**网络时间**（GitHub 响应头 Date）
- 本地只缓存上次联网的真实时间戳
- 用户改手机时间没用

### 5. 代码混淆
- ProGuard/R8 混淆 JS 代码
- 验证逻辑拆成多个文件，打乱顺序
- 关键密钥用多字符串拼接（比如 `'ab' + 'cd' + 'ef'`）

### 6. 防抓包重放
- 激活请求里加时间戳 + 随机数
- 超过 5 分钟的请求拒绝

### 7. 防暴力破解
- 激活码输错 5 次 → 锁定 1 分钟

## 三、数据结构（activate.json）

```json
{
  "version": 1,
  "enabled": true,
  "codes": [
    {
      "hash": "a3f8b2c9d4e5f6...",
      "name": "张三-车机",
      "appType": "car",
      "tier": "pro",
      "status": "active",
      "expireAt": "2027-12-31T23:59:59Z",
      "deviceEncrypted": "U2FsdGVkX1+8xY7z9...",
      "activatedAt": "2026-11-10T10:00:00Z"
    }
  ]
}
```

| 字段 | 加密 | 说明 |
|---|---|---|
| `enabled` | 否 | 全局开关：是否要求激活（远程可关闭） |
| `hash` | 否 | 激活码 SHA-256 哈希 |
| `name` | 否 | 备注名字（管理员自己看的） |
| `appType` | 否 | `car`/`phone`/`both`，区分车机版/手机版 |
| `tier` | 否 | 授权等级：`trial`/`pro` |
| `status` | 否 | `unused`/`active`/`disabled` |
| `expireAt` | 否 | 过期时间（ISO 格式） |
| `deviceEncrypted` | **AES加密** | 设备 ID + 型号 + 激活时间 |
| `activatedAt` | 否 | 激活时间 |

## 四、App 端完整流程

### 1. 启动流程（每次打开）

```
App 启动
    ↓
读取全局开关 enabled：
  ├─ false → 直接进主界面（不要求激活）
  └─ true → 继续
    ↓
获取设备指纹（SHA256(android_id + 型号 + 屏幕密度)）
    ↓
读本地存储：
  - 有没有签名令牌？
  - 上次联网验证是什么时候？
    ↓
┌─ 24 小时内已验证过 ───────────────┐
│                                    │
│  直接验证本地令牌签名               │
│  ├─ 签名对 → 直接进主界面           │
│  └─ 签名错 → 弹激活框               │
└────────────────────────────────────┘
    ↓
┌─ 超过 24 小时未验证 ────────────────┐
│                                    │
│  后台静默联网拉取 activate.json      │
│  验证：                              │
│    ① 全局开关 enabled 还开着吗？     │
│    ② 我的设备在已绑定列表里吗？      │
│    ③ 激活码过期了吗？                │
│    ④ 被禁用了吗？                    │
│                                    │
│  ├─ 都正常 → 保存新令牌 → 进主界面   │
│  ├─ 被删/过期/禁用 → 弹失效提示      │
│  └─ 没网/拉取失败 → 宽限 7 天，照常  │
└────────────────────────────────────┘
    ↓
┌─ 本地没有令牌 ──────────────────────┐
│                                    │
│  自动检测：设备指纹在已绑定列表里吗？ │
│                                    │
│  ├─ 在（自动激活）→ 保存令牌 → 进主界面 │
│  └─ 不在 → 弹激活码输入框           │
└────────────────────────────────────┘
```

### 2. 激活码输入流程（第一次）

```
弹出全屏激活码界面（挡住所有功能）
    ↓
输入框：自动格式化（每4位加横杠）、自动转大写、自动忽略空格/横杠
    ↓
[激活] 按钮
    ↓
验证输入格式（16位，无歧义字符）
    ↓
计算激活码哈希 → 联网拉取 activate.json
    ↓
查找这个哈希：
  ① 存在吗？
  ② status 是 unused 吗？
  ③ appType 匹配吗？（车机版只能用 car 的码）
  ④ 过期了吗？
    ↓
全部通过
    ↓
提交绑定：更新 json，写入 deviceEncrypted、status=active
    ↓
返回签名令牌（deviceId + expireAt + signature）
    ↓
保存令牌到本地
    ↓
进入主界面
```

### 3. 失败提示文案

| 错误 | 提示文案 |
|---|---|
| 激活码不存在 | "激活码不存在，请检查输入" |
| 已被使用 | "激活码已被使用，一个码只能绑定一台设备" |
| 已过期 | "激活码已过期，请联系管理员续期" |
| 已禁用 | "激活码已失效，请联系管理员" |
| 类型不匹配 | "此激活码不适用于当前版本" |
| 网络错误 | "网络异常，请检查网络后重试" |
| 输错 5 次 | "输错次数过多，请 1 分钟后再试" |

## 五、容错机制

| 场景 | 处理方式 |
|---|---|
| **没网时打开** | 本地有令牌 → 宽限 7 天，照常使用 |
| **json 拉取失败/格式错** | 用本地缓存的令牌，宽限 7 天 |
| **连续 7 天没联网** | 第 8 天弹"请联网验证授权状态" |
| **本地令牌损坏** | 清除令牌，重新走激活流程 |
| **设备换了（恢复出厂）** | 自动激活失败 → 弹输入框 → 重新激活 |
| **json 文件太大** | 按状态分文件：unused 列表 + used 列表 |

## 七、激活码规则

| 规则 | 说明 |
|---|---|
| **格式** | 16 位，分 4 组，每组 4 位：`A8F3-K2D9-7B1C-E5H0` |
| **字符集** | 无歧义字符：去掉 0/O、1/l/I，避免看错 |
| **一次性** | 一个码只能绑定 1 台设备，绑定后不能再绑第二台 |
| **自动激活** | 只要设备在绑定列表里，打开 App 自动进，不用再输码 |
| **有效期** | 生成时可选：永久 / 1 年 / 自定义日期 |
| **远程控制** | 你在后台改状态、改有效期，对方下次联网就生效 |

## 八、用户体验细节

### 输入体验
- 自动格式化：每 4 位自动加横杠
- 大小写不敏感：输入小写自动转大写
- 自动忽略空格/横杠：粘贴 `a8f3 k2d9 7b1c e5h0` 也能识别
- 粘贴自动清理格式

### 过期提醒
- 过期前 **7 天**：每次打开弹小提示"授权将于 X 天后到期，请联系管理员续期"
- 过期前 **1 天**：更明显的提示
- 过期后：完全进不去，只能输新激活码

### 换设备引导
- 弹激活框时加一行小字："换设备了？请联系管理员解绑旧设备后再输入激活码"

### 免费试用期（可选）
- 新用户第一次打开，免费试用 7 天
- 7 天内全部功能正常
- 7 天后弹激活框

## 九、隐私合规

### 收集的信息（最小化）
- ✅ 设备唯一标识（用于绑定）
- ✅ 设备型号（管理员看的，知道是什么设备）
- ❌ 不收集位置
- ❌ 不收集通讯录
- ❌ 不收集使用行为

### 用户告知
第一次弹激活框时，下面加一行小字：
> 为了保护您的授权安全，我们会收集设备型号和唯一标识用于绑定授权。数据加密存储在云端，不会泄露。

## 十、兼容性设计

### 旧版本兼容
- json 里有全局开关 `enabled: true/false`
- 你可以先把激活功能写进代码，但默认关闭
- 等你测试满意了，远程改成 `true`，不用重新编译发版

### 车机版/手机版分开
- 激活码加 `appType` 字段：`car`/`phone`/`both`
- 车机版的激活码不能用在手机版上，反之亦然

## 十二、安全边界（实话实说）

| 攻击方式 | 能不能防住 |
|---|---|
| 普通人拿到 APK，没有激活码 | ✅ 防住，进不去 |
| 别人猜激活码 | ✅ 防住，16 位组合猜不到 |
| 你想收回权限 | ✅ 防住，改 json 状态就行 |
| 改手机时间绕过过期 | ✅ 防住，用网络时间 |
| 本地伪造激活状态 | ✅ 防住，签名令牌验证 |
| 抓包看到 json 文件 | ✅ 防住，只有哈希 + 加密设备信息 |
| 懂技术的反编译 APK，改验证逻辑 | ❌ 防不住（但你就几个人用，谁会这么干） |
